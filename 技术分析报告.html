01 · 结论速览 TL;DR

一句话：它不是投屏工具，是网约车司机的车机多开接单工作台；投屏只是承载手段，而手机端与车机端是同一 APK 的两个互补角色。

角色分工
编码 → 解码
手机端 PhoneCastVideoCoder 编码，车机端 car.cast.MyVideoDecoder 解码。手机采集被控，车机渲染控制。
提权方向
车机是 ADB 客户端
车机端内置 adblib.AdbProtocol + AdbKeyPair，主动 RSA 认证连手机的 5555；电脑"激活工具"只执行 adb tcpip 5555。
自研程度
移植 scrcpy
commoncast.scrcpy 包内是 scrcpy 的 Java 侧代码：坐标换算、多点触控、视频裁剪均非自研。
真实用途
接单工作台
字段 taxiPackageName、DiDiOrderInfoBean、RobotOrderOcrBean、载客 TTS 文案，构成完整的抢单链路。
代码保护
SecShell 剥 class_defs
classes.dex 仅 640 个类定义且无 com.sven.*；但 hh.jar（提权服务）完全裸奔，2430 类可反编译。
最高风险
无认证 adbd
tcpip 5555 后 adbd 无二次认证，而连接指引恰是"车机连手机热点"——同网段即等于拿到手机 shell。

03 · 架构与数据流

视频与触控构成一个闭环：画面单向上传，操作反向回注。

三条通道：ADB 提权（虚线，车机→手机）、媒体流（手机→车机）、触控回注（车机→手机）。多窗口路径下媒体流走 shell 进程，无需 MediaProjection 授权框。
两条采集路径
单窗口 PhoneWholeCastActivity · MediaProjection · 需授权框 · 整屏压缩 多窗口 MultiViewActivity · shell 虚拟屏 · 无授权框 · 按车机 dpi 布局
两条路径的差异，同时决定了"画面大小"和"要不要点授权框"。
应用列表同步（多开闭环）
手机枚举 CarSyncAppInfoBean + 图标 → 车机 CarDuoKaiFloatAppAdapter 展示 → 选中后 startActivityAsUser 拉到虚拟屏
最后一步必须有 shell 权限，这就是"多窗口投屏"锁在 ADB 激活后的技术原因。

06 · 传输层与编解码

共享库承载传输，但编解码器分属两端包命名空间 —— 这是判定角色方向最可靠的证据。

层实现归属证据
编码H.264 + AAC手机端PhoneCastVideoCoder、createVideoFormat(mediaC, pushWidth, pushHeight)、VIDEO_WIDTH/HEIGHT
解码MediaCodec 解码车机端car.cast.MyVideoDecoder、audio.MyAudioDecoder、demuxer_stall_500_count
可靠通道Netty共享lancomm.netty.MyMessageDecoder、包内含 io.netty.bootstrap.ServerBootstrap
视频通道UDP + 自研流控共享RemoteUdpFlowHelper UdpSendCastInfo UdpResendItem BytePoolManagerForUdp/Video
设备发现NSD/mDNS + 扫码共享base.nsd.NsdHelper、手机 CustomScannerActivity ↔ 车机 CheckPhoneScanConnHelper
加密SPAKE2 + ECDH + AES/GCM + TLS共享libspake2.so、字符串 AES/GCM、conscrypt
协商字段deviceType 枚举显式协商carWidth/carHeight/densityDpi/castType/configIndex/isLand/isSingleFull
正面评价局域网通道用了 SPAKE2（口令认证密钥交换）+ ECDH + AES/GCM，不是明文裸传，比多数同类投屏工具规范。

推断 谁是 TCP 服务端：从 PhoneConnectHelper.sendInitDataToCar 命名倾向"手机主动推送初始化数据"，但 ServerBootstrap 在共享库里两端可用，故不作结论。

07 · 提权链路（完整时序）

所谓"ADB 激活"不是配置项，而是一条跨设备的权限移交链。

1电脑运行 激活脚本Windows.bat，实际只执行 adb tcpip 5555（脚本原文已核验，另含设备计数与提示）
2手机 adbd 转为监听 TCP 5555，该模式无网络侧二次认证
3车机端用内置 adblib.AdbProtocol + AdbKeyPair（RSA）连上手机 5555
4推送服务负载到 /data/local/tmp/my_car_server_*（另有 ls / rm 清理逻辑）
5app_process -Djava.class.path=… com.sven.adbserver.MyNewServer 以 shell uid 常驻；停止靠 ps -ef | grep … | xargs kill -9
6主 App 通过 IMyAdbService / IMyAppService AIDL 调用该服务；RemoteAdbLocalSocketHelper 做本地 socket 桥接

09 · 架构事实：移植了 scrcpy

多窗口投屏的坐标换算、多点触控与视频裁剪并非自研，而是 scrcpy（Apache 2.0）的 Java 侧移植。

com.sven.commoncast.scrcpy 包内容 
AffineMatrix   Orientation   Point   Pointer
PointersState  Position      Size    TouchEventHelper
VideoFilter    oldcontrol/OldPointer
oldcontrol/OldPointersState
类名与 scrcpy 的 device/ 与 /input 一一对应；oldcontrol 对应 scrcpy 旧版控制协议。
这解释了为什么必须提权

scrcpy 的工作方式就是"PC 用 adb 在手机上以 shell 身份跑一个 server，由它创建虚拟屏、采集、编码，再回传"。本产品把"PC"换成了车机、把"回传 PC"换成了回传车机 —— 因此它必须获得 shell 身份，也就必须走 app_process。

副作用是好的：shell 进程采集不需要 MediaProjection 授权框（与 screenrecord 同理）。所以"画面小"和"授权框骚扰"是同一个开关解决的。

10 · 安全面评估

高危 · 无认证 adbd 暴露在同网段 tcpip 5555 后网络 adb 无二次认证，而 App 的连接指引正是「车机连接手机的 WiFi 热点」。等于主动开一个局域网，把 adb 暴露给一台装了不明 APK 的第三方车机及同热点下任何设备。缓解：优先走 AdbWirelessHelper.startPair（Android 11+ 无线调试配对，每次重连需确认）；用完 adb usb 收回；不要把该热点共享给其他设备。
中危 · 权限组合的能力上限 无障碍（读全屏 + 点击）+ ADB 提权（造屏 / 注入 / 启停 App）+ OCR + 高德定位 + 全量设备标识 + 字节系广告 SDK + 自更新（REQUEST_INSTALL_PACKAGES）。同时包内存在 11MB 的 libmlkit_google_ocr_pipeline.so。请把它当成"给了第三方 App 整台手机的 shell"来决策。
中危 · 一次"拒绝"即静默失效 实测确认：在投屏授权框点「拒绝」会把 PROJECT_MEDIA 打回 ignore，之后所有投屏被静默掐断 —— App 不报错，只是连不上。这是本次排查的根因。
可收紧 · 无权限保护的导出组件 ChangeOrientationService 与 PhoneService 均 exported=true 且未见自定义权限保护，同机任意 App 可尝试调用。车机端导出面反而小（仅 2 个）。
正面 · 通道加密规范 SPAKE2 + ECDH + AES/GCM + TLS，局域网传输非明文。

12 · 落点与建议

画面小到离谱
根因是走了手机端 PhoneWholeCastHelper 整屏镜像：1440×3168 / 640dpi 被等比压进车机屏，缩放比约 0.227。 能调的「窗口比例」被写死在 ADB 激活之后。正解：激活 ADB → 切 MultiViewActivity 多窗口 → 按 carWidth/carHeight/densityDpi 建虚拟屏。
投屏授权框
只在手机端、只在单窗口路径上存在（MediaProjection 是 App 级授权）。多窗口路径采集发生在 shell 进程内，该框不存在。 当前三层保障：PROJECT_MEDIA=allow（实测跨重启保住）→ 无障碍 ScreenCaptureAutoClickHelper 自动点 → 自建守护 App 开机自愈。唯一破坏动作是点「拒绝」。

建议顺序

1若接受提权：走 无线调试配对（startPair）而非 tcpip 5555 激活 ADB，切多窗口模式 —— 一次解决画面与授权两件事
2若不接受提权：保持单窗口，依赖 PROJECT_MEDIA=allow + 无障碍自动点 + 自建守护 App 自愈；避免点「拒绝」
3无论哪条：车机侧缩放模式设为"填充/拉伸"，投屏分辨率对齐车机屏原生分辨率
4把 adb tcpip 5555 视为临时状态，用完即收回
